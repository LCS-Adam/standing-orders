# Troubleshooting

One table. Find the symptom you are looking at, then go read the page it names; this document
does not repeat the fix in full, it points at the place the fix already lives.

| Symptom | What is happening | Where the fix is documented |
|---|---|---|
| A subagent spawn gets denied by a hook | The `require-agent-model.sh` `PreToolUse` hook vetoes any dispatch that does not name a model or point at an agent definition with a `model:` pin, because the alternative is silently inheriting the parent's model | [docs/getting-started.md, "Troubleshooting"](getting-started.md#troubleshooting) |
| `/ponytail-review` produces nothing | It is not shipped by this repo. It comes from an upstream plugin that `harness upstream` clones and your tool installs; a machine that has not run that install has no such command | [docs/upstream-sources.md](upstream-sources.md), the ponytail section; [docs/operating-process.md, step 4](operating-process.md#step-4-review) |
| `/deep-plan` says it cannot call the advisor | The session has no `advisor` tool wired up (some plans and hosts do not expose one). The CLAUDE.md fallback applies: tell the session there is no advisor here and dispatch a stand-in reviewer at or above the builder's tier instead of skipping the review | [docs/glossary.md, the `advisor` entry](glossary.md#advisor) |
| The gate fails and names the counts check | A doc states a count (files, subagents, skills, commands) that no longer matches the repo, usually after adding or removing one of those. Update the sentence in the doc the failure names, not the check | [docs/first-day.md](first-day.md), the gate output; verify.sh, check 12 |
| The gate fails and names generated files as stale | [`docs/reference.md`](reference.md) or `plugins/` was hand-edited, or an agent/skill/command changed without regenerating. Run `scripts/gen-reference.sh > docs/reference.md`, and `harness build-plugin --tool auggie` if `plugins/` is committed, in the same commit as the change that made them stale | [docs/getting-started.md, "Running verify"](getting-started.md#running-verify); verify.sh, check 13 |
| The gate fails on a banned glyph | An em dash, curly quote, ellipsis character, or similar landed in a client-facing file. Run the `perl -CSD` scan named in AGENTS.md against the file it names and replace what it finds with straight ASCII | [AGENTS.md, "Writing for people outside the team"](../AGENTS.md#writing-for-people-outside-the-team); verify.sh, check 8 |
| Tests were green in a worktree and fail on the first run after merging to the main checkout | A worktree does not contain everything the main checkout does; something the suite depends on (a gitignored scratch directory, local data) can be invisible inside a worktree. Run the suite's real command in the main checkout and expect the first post-merge run to differ from every pre-merge run | [docs/anti-patterns.md, "Worktree green, main red"](anti-patterns.md#worktree-green-main-red) |
| A backgrounded agent's result never arrived | The agent finished, but its final message never reached the caller; this is a known failure mode of backgrounding, not a sign the work did not happen | [docs/anti-patterns.md, "The report lost when a backgrounded agent goes idle"](anti-patterns.md#the-report-lost-when-a-backgrounded-agent-goes-idle); read the report file the dispatch brief named under `runtime/` |
| The agent says the tests pass and they do not | Re-run the suite's real command yourself rather than taking a summary at face value | [docs/anti-patterns.md, "The timeout wrapper that faked a clean review"](anti-patterns.md#the-timeout-wrapper-that-faked-a-clean-review) |
| The agent stopped following an instruction you gave an hour ago | The context window has filled enough that the early instruction is competing with everything said since; more of the same session will not fix it | [docs/context-window-management.md, "Symptoms and fixes"](context-window-management.md#symptoms-and-fixes); [docs/context-health.md, "What to do, by situation"](context-health.md#what-to-do-by-situation) |
| A file the installer should have written instead says `(exists, differs - use --force)` | The installer found a file already at that path with different content and declined to overwrite it | [docs/getting-started.md, "Troubleshooting"](getting-started.md#troubleshooting) |
| `harness verify` reports on the harness checkout, not your project | `harness verify` is the harness repo's own scrub gate; it always scrubs the directory it is installed in, never the project you happen to run it from | [docs/operating-process.md, step 6](operating-process.md#step-6-close) |
| `/next-step` finds nothing to do | There is no `phases/` directory yet, which only exists once a build spans sessions | [docs/getting-started.md](getting-started.md), `harness add phase`; [docs/planning-large-builds.md](planning-large-builds.md) |
| A resumed session asks what file to read first | The pasted resume block did not name its own file in its own read list, so the session has nothing pointing back to the rest of the handoff | [docs/anti-patterns.md, "The orphaned resume block"](anti-patterns.md#the-orphaned-resume-block); [AGENTS.md, "Session handoff"](../AGENTS.md#session-handoff) |
